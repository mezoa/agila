### Answers to the 9.L1 questions (proposals; nothing is built or decided)
**1. hit@3 and the refusal rate.**
- For each of the 14 answerable questions: `search(conn, q, min_similarity=-1.0)` gives the raw top 3; a **hit** when any of the 3 has `source` equal to the key's document (V94). hit@3 = hits / 14, and the same per half (dev, held-out). One miss = 1/14 = 7.1 points; 12 of 14 = 0.857 passes M1. Within a half the step is larger: if a half holds 7 answerable questions, one miss = 14.3 points (the real split is U49).
- Report a second number next to it: **false refusals** = answerable questions whose `best_similarity` is below the threshold (they would be refused even when the right page is in the top 3). This keeps retrieval quality and threshold choice apart. Whether M1 counts raw top 3 or top 3 after the threshold is a choice for Eo (the PRD calls M1 "retrieval quality", which reads as raw).
- For the 6 unanswerable: **refused** when `best_similarity < threshold` (V94). This is M2 "with no model call" (V92). Refusal count = refused / 6; one miss = 16.7 points. A refusal by the model (`answerable: false`) is reported separately and does not count for M2.
- If several right documents exist for one question, the key lists all of them and any one counts (to decide when writing the key format; not read today).
- Honest limit, wording for the report: "14 and 6 questions, a regression check, not proof: one miss moves hit@3 by about 7 points and the refusal count by about 17; a half moves by about twice that."

**2. A separate eval database.**
