Decided by Eo 2026-10-20 (U20) | `httpx` is declared in `pyproject.toml` (it was only transitive); certificate checks stay on, with no unverified fallback. Private-address block, redirect cap of 5, 5 MB cap and content-type check were built on Day 5 (2026-10-21): see "Redirects", "Download safety" and "Download limits" |
| Download timeout | The 15-second timeout is a TOTAL wall-clock limit for the whole download, enforced by our code with `asyncio.timeout`; httpx's own per-step timeouts are off | FR2 says "15-second timeout"; a per-step limit can add up to far more (V34) | Tested with `httpx.MockTransport`: a stall of 5 s with a 0.2 s limit ended in about 0.2 s (V39) |
| URL normalization | PRD rules only (FR7): lowercase scheme and host, no fragment, no `utm_*`, `fbclid` or `gclid` parameters (names compared ignoring case), no trailing slash on the path (so `http://x.com/` and `http://x.com` are one). Kept as given: path case, parameter order, `www.`, `http` versus `https`, ports. **Not normalized yet:** parameter order, default ports and `http`/`https`, other tracking parameters (`ref`, `mc_cid`, `igshid`), `www.`, percent-encoding case and non-ASCII hosts, `user:password@`, path case, repeated slashes and `index.html`, percent-encoded parameter names, `#!` routes (dropped as fragments). Only ONE trailing slash is removed | Eo's decision 2026-10-20 (U22): do exactly what the PRD says and no more | Two URLs that differ in any listed case get two identity keys and save twice. Each case is pinned in `tests/test_urls.py` so a later change is deliberate |
| Page text rules | A page is rejected if `trafilatura.extract` returns `None`, if it has under 200 characters (whitespace collapsed to single spaces), or under 3 sentences. **Assumed rule (FR2 gives none):** a sentence is a piece cut at `.`, `!` or `?` followed by whitespace, or at a line break, but not after `e.g.`, `i.e.`, `vs.`, `Mr.`, `Mrs.`, `Ms.`, `Dr.`, `Prof.`, `Fig.`, `approx.` or dotted initials such as `U.S.`; a piece of fewer than 3 words is joined to the previous one | `extract` alone is not enough: a menu-only page returned `"A\nB"` and a one-line page returned its line (V32). Decided by Eo 2026-10-20 (U23) | Headings of 3 or more words count as sentences, and a menu of any length counts at most once (V40). Only made-up fixtures were tried; real pages: Day 5 |
| Redirects | Followed BY HAND (`follow_redirects=False`), at most 5: five redirects are allowed, the sixth is refused ("The page redirects more than 5 times."). The next address is `response.next_request.url` (httpx has already resolved a relative `Location`). Every hop repeats the scheme check and the address check. A loop is detected by remembering the URLs seen, compared WITHOUT the fragment ("The page redirects in a circle."). A 3xx without a usable `Location` is just a non-200 status | FR2: at most 5 redirects, address check after every redirect. httpx does not validate a `Location` (it builds `ftp://`, empty and malformed targets, V44), so our code must. Replaces the temporary "redirects are not supported yet" sentence (Eo agreed 2026-10-20, built 2026-10-21) | Tests: `test_web.py` redirect section (MockTransport). Real links: Eo's 5-link sample |
| Download safety | Agila checks every address a link resolves to, before the first request and again after every redirect, and refuses private, local and reserved ones (`netcheck.py`, the V41 rule). It asks the system name lookup for ALL addresses, never uses the "numeric only" flag, and refuses if the lookup fails or if ANY address is blocked. Odd spellings such as `2130706433` or `0x7f.0.0.1` are covered because we judge what the lookup returns, not the text of the link. **Three gaps stay open on purpose:** (1) a name can give our check a harmless answer and the real connection a different one (DNS rebinding), because httpx looks the name up again when it connects; (2) a public server can forward our request to something on my home network, and we cannot see that; (3) a connection that is kept open and reused is checked when it is opened, not on every request. This is acceptable for a one-user tool that runs only on my laptop and only fetches links I type. **It MUST be revisited before the Discord bot (block o) lets anyone but me save links.** We do NOT replace httpx's private `transport._pool` to close gap 1, because it can break silently on an httpx upgrade (U28). The optional "connect to the checked address" idea (plan step 2) was dropped by Eo on 2026-10-21 to save time | FR2 says to block localhost, private and link-local addresses, checked again after every redirect. Research V41 to V47 | Proxy environment variables are ignored (`trust_env=False`, tested, U26). Tests cannot reach the internet (see "Test network guard"). Linux behavior of odd IPv4 spellings is untested (U24, pending until block k) |
| Download limits | Page body: at most 5 MiB (5,242,880 bytes) [assumed, FR2]; a larger declared `Content-Length` is refused before any body is read, and a body that passes 5 MiB while streaming is refused (never cut). Content type: `text/html`, `application/xhtml+xml` or `text/plain` only (case and parameters ignored); a response with NO `Content-Type` is refused. We send `Accept-Encoding: identity` and refuse any answer whose `Content-Encoding` is not identity ("compressed and was not accepted"); the body is read raw so no decompression code runs. A web page needing more than 200 chunks is refused before embedding; text and Markdown are not limited. Charset comes only from the `Content-Type` header (default UTF-8, undecodable bytes replaced) | FR2 lists these limits. Eo answered Q5 and Q6 on 2026-10-21. A 40 KB gzip became one 40 MB chunk when decompressed (V45), so compressed bodies are not accepted | A header that says too LITTLE silently cuts the page and cannot be detected (V45). Sites that only serve compressed answers will fail: revisit if the 5-link sample shows many. A `<meta charset>` in the HTML is not read |
| Test network guard | `tests/conftest.py` has an autouse fixture that makes any test fail if it connects to a non-loopback address or looks up a real host name (it patches `socket.getaddrinfo`, `gethostbyname`, `gethostbyname_ex`, `socket.connect`, `connect_ex` and, on Windows, `IocpProactor.connect`). Only loopback and `localhost` are allowed. An attempt raises `NetworkBlockedError` AND is recorded, so a library that swallows the error still fails the test at teardown. No switch turns it off. Research and scratch scripts follow the same rule: loopback or stubs only | Eo's decision 2026-10-21. asyncio's default Windows loop does not call `socket.connect` (U29), so patching only that would leave a hole | Python-level only: `libpq` (Postgres) and other native code are not covered. Its own tests (`test_netguard.py`) swap the real functions for recorders, so even a broken guard sends nothing |
| URL fields on a web document | `documents.source_url` = the link exactly as given (spaces trimmed); `normalized_url` = the normalized form; `identity_key` and `source_label` = the normalized form; `source_type` = `web`; `content_hash` = SHA-256 of the extracted text, not of the HTML. Title: `--title`, else the page's own title, else the normalized URL. No URL is stored on `chunks`. The page is downloaded from the link as given, not the normalized form | PRD FR7: the identity key of a web page is its normalized URL; the columns already exist in `0001_init.sql`, so no migration was needed | Saving it again: see "Same item saved again" (block g) |
| Same item saved again (FR7) | **Eo's option 1 (2026-10-22):** migration `0002_identity_index_web_only.sql` narrows the unique index `documents_active_identity` to `status = 'active' AND source_type = 'web'`, so only web pages are limited to one active copy per identity. On a save, the active documents with the same identity (web: normalized URL; text and Markdown: `source_type:label`) are compared first: identical content hash -> "Already saved, unchanged" and nothing is written or embedded (also with `--replace`); changed web page, or any save with `--replace` -> every active copy is marked `superseded` BEFORE the new row is inserted, in the same transaction, and the new row's `supersedes_id` points to the newest old copy; a changed text or Markdown note without `--replace` -> both kept active, with a warning naming each older note (id and title). Only ACTIVE documents count as the same item: a link whose only copy is archived is saved as a new active copy (assumed, Eo Q2) | PRD FR7 and its acceptance sentences. The 0001 index allowed one active document per identity of ANY type, which made "two different notes with the same label both exist" impossible (DEVIATIONS 4) | The database no longer stops two active text notes with one label; the save code warns instead. A failed save rolls the supersede back too (FR8, tested). "Absent from answers" is proven in block h (FR9 test, DEVIATIONS 25) |
| Archive and delete | `archive ID`: active -> archived only; `unarchive ID`: archived -> active; chunks are never touched, so unarchiving brings the document back exactly. Unarchiving a web page while a newer copy of its link is active is refused with one sentence (Eo Q6). `delete ID` takes one numeric id from `list`, never a title or pattern; without `--yes` it is a dry run that prints title, type, date and chunk count and deletes nothing (Eo Q1); with `--yes` the document goes and its chunks with it (`ON DELETE CASCADE`); a newer copy's `supersedes_id` becomes NULL. `list` shows id, local date, status, visibility and title for every document, newest first | FR18, FR19, FR20; a delete cannot be undone, so one id at a time and a dry run first | No undo until the backup of block k. The Obsidian note side (FR28) is block n. These are temporary `agila.ingest` commands until the CLI of block j |
| Search and threshold | `retrieval.search` returns up to 3 passages from ACTIVE documents only, best first: `ORDER BY c.embedding <=> question, c.id LIMIT 3` (the `c.id` tie-break keeps equal scores in a stable order, V55); similarity = 1 - cosine distance (V54). Each passage carries chunk id, text, heading, page, document title, source (the link for a web page, else the label), saved date and similarity. Passages below the threshold are dropped, also the 2nd and 3rd when the best passes (Eo Q3); `best_similarity` is always returned (None for an empty library). Threshold: `PROVISIONAL_MIN_SIMILARITY = 0.70`, compared with `>=`, a named constant in `retrieval.py` (Eo Q1, Q2), chosen inside the gap seen on 8 questions (unanswerable up to 0.603, answerable from 0.786, V58). The question is embedded by ONE function, `embed.embed_question`, like a passage with no prefix (V56); BGE's query instruction is a switch, OFF by default (U10). Search is read-only and never imports a model; it never touches `last_asked_at` | FR9, FR10, FR13 (threshold part), FR35. A constant, not a `settings` row: one reader, no migration, and the block l change is a one-line commit (PRD section 10 lists only `embedding_model` and `embedding_dim` in `settings`) | **PROVISIONAL**: the threshold is set on the dev half of the golden set in block l (U31). The sentence "I couldn't find this in your saved material" and the `last_asked_at` update belong to the ask flow (blocks i and j), not to search. No visibility filter until `--private` (block p) |
