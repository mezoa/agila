- **Prefix: kept** (`embed.USE_QUERY_INSTRUCTION = True`, questions only; stored chunk vectors are unchanged, so nothing was re-embedded). Dev hits 6 of 7 both ways; gap (lowest answerable best minus highest unanswerable best) -0.049 without, **-0.037 with**. Rule used (plan Q6): keep the prefix only if dev hits do not drop AND the gap gets wider (here: less negative).
- **Threshold: 0.68** (`retrieval.PROVISIONAL_MIN_SIMILARITY`, compared with `>=`; name kept until the full run). Rule used (plan Q5, `evaluate.propose_threshold`): try 0.00 to 1.00 in steps of 0.01, count dev errors (answerable refused plus unanswerable let through), take the highest run of values with the fewest errors and its middle, rounded up. Result with the prefix: **2 dev errors**: answerable **Q03 (0.630) and Q05 (0.621) are refused**; **no unanswerable question is let through** (highest 0.657, Q17). Without the prefix the same rule gave 0.69, also with 2 errors.
- **Flaw in the prefix rule:** it has no minimum margin. The gap moved by 0.012 (from -0.049 to -0.037) and the hits did not move, a difference that one more or one fewer question could reverse. **The next evaluation plan must add a minimum margin** (for example: keep a change only if the gap widens by at least a set amount or the hits rise), decided before the numbers are seen.
- **Q08 is a miss either way** (its phrase is in none of the top 3, with or without the prefix). Its best score, 0.703, is above 0.68, so in a full answer run Q08 reaches the model with passages that do not hold the answer; the model's `answerable: false` is then the only guard.
- Not decided here: the held-out half, the baseline, and the rename of `PROVISIONAL_MIN_SIMILARITY` (all after the full run, block l step 11).
